SÉCURITÉ CRITIQUE
  [✅] SEC-01  Génération de mots de passe — str_shuffle() remplacé par random_int() (CSPRNG)
               Fichiers : AdminController.php, ProfController.php
               Raison : str_shuffle() n'est PAS un générateur cryptographiquement sûr (PRNG standard PHP)
               Fix : nouvelle méthode privée generateSecurePassword() utilisant random_int(0, strlen($chars)-1)

  [✅] SEC-02  PasswordResetRequest::markResolved — mot de passe en clair supprimé de generated_password
               Fichier : app/Models/PasswordResetRequest.php
               Raison : La colonne generated_password stockait le mdp en clair — compromission BDD = tous les resets exposés
               Fix : La colonne est maintenant remplie avec "[REINITIALISE]" (marqueur non sensible)

  [✅] SEC-03  processCreateStudent — 'password123' hardcodé remplacé par mdp généré aléatoirement
               Fichier : app/Controllers/AdminController.php
               Raison : Tous les étudiants créés manuellement avaient un mot de passe identique connu
               Fix : generateSecurePassword(10) + stockage dans import_identifiants + reset_password_result en session

  [✅] SEC-04  exportAllStudentsCsv — suppression de la colonne mot de passe de l'export
               Fichier : app/Controllers/AdminController.php
               Raison : COALESCE(i.mot_de_passe_clair, 'password123') exportait les mdp en clair dans un fichier téléchargeable
               Fix : La colonne "Mot de passe" a été retirée de l'export TXT/CSV des utilisateurs

  [✅] SEC-05  Login brute-force — rate limiting ajouté
               Fichier : app/Controllers/AuthController.php
               Raison : Aucune limite sur les tentatives de connexion → brute-force illimité
               Fix : Blocage après 10 tentatives échouées, fenêtre de 15 minutes, compteur par IP via session

  [✅] SEC-06  ProfController::resolvePasswordReset — vérification d'autorisation ajoutée
               Fichier : app/Controllers/ProfController.php
               Raison : Un professeur pouvait réinitialiser le mdp de n'importe quel étudiant, même hors de ses exercices
               Fix : Vérification que l'étudiant a soumis un projet dans un exercice du professeur connecté

  [✅] SEC-07  public/uploads — .htaccess sécurité ajouté
               Fichier : public/uploads/.htaccess (nouveau)
               Raison : Les fichiers PDF uploadés étaient accessibles directement par URL, risque de PHP upload
               Fix : Désactivation de l'exécution de scripts, restriction aux .pdf uniquement

  [✅] SEC-08  storage/logs — .htaccess de blocage ajouté
               Fichier : storage/.htaccess (nouveau)
               Raison : Les logs d'erreurs étaient accessibles via URL directe
               Fix : Deny from all

  [✅] SEC-09  mkdir uploads — 0777 → 0750
               Fichier : app/Controllers/StudentController.php
               Raison : Les droits 0777 (world-writable) permettent à n'importe quel processus d'écrire dans uploads/
               Fix : 0750 (propriétaire + groupe seulement)

ADDENDUM - CORRECTION DU FLUX MOT DE PASSE (post-analyse)
----------------------------------------------------------
Le flux de distribution physique des mots de passe temporaires est INTENTIONNEL et CONSERVE.
L'admin cree les comptes, voit les mots de passe temporaires, les imprime/distribue,
et les utilisateurs les changent au premier login (first_login=1 -> 0).

Ce qui a ete corrige (et non supprime) :
  - exportAllStudentsCsv : COALESCE(mdp_clair, 'password123') -> CASE WHEN first_login=1
    * Si compte pas encore active : affiche le vrai mdp temporaire (ou 'A distribuer')
    * Si compte deja active (first_login=0) : affiche 'Deja modifie' -> pas de fuite du mdp actuel
  - downloadImportCsv : ajout WHERE first_login=1 -> n'exporte QUE les non-actives
    + ajout nom/prenom dans l'export pour faciliter la distribution

La colonne mot de passe dans les exports est CONSERVEE car necessaire au flux metier.
